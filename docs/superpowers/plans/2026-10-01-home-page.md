# CodeAdda Home Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `/` → `/sql` redirect with a static, offline-capable CodeAdda home page laid out like the labs.chaicode.com home page, with original copy and numbers computed from the real content.

**Architecture:** A new `apps/web/src/home/` folder holds pure data (`homeContent.ts`), inline icons (`icons.tsx`), the hero code card (`HeroDemo.tsx`) and the page (`HomePage.tsx`). The page reads the existing content registry, navigation helpers and progress store; it never imports Monaco or the database engine. Small edits expose the upcoming-labs list from the registry, add one colour token and three animations, swap the `/` route, and move the e2e start URL. The lab screen becomes lazy-loaded last.

**Tech Stack:** React 19, React Router 7, Vite, TypeScript (strict), Tailwind v4 (`@theme` tokens, no config file), Vitest + Testing Library (jsdom per file), Playwright, PGlite (only in the truth test).

**Spec:** `docs/superpowers/specs/2026-10-01-home-page-design.md`

## Global Constraints

- **No git commits, adds or stashes by the implementer.** The user commits on their branch `feature/home-page`. Every "Commit" step in the usual template is replaced by "Leave uncommitted"; verification is by running the commands, not by git state.
- No new npm dependencies. No `dark:` Tailwind utilities anywhere under `apps/web/src/home`. No raw hex colours outside `apps/web/src/styles/tokens.css`. No external URLs (fonts, icons, images); the e2e offline guard aborts every non-localhost request.
- Copy is original. Nothing quoted or closely paraphrased from labs.chaicode.com. The word "Chai" must not appear in the page. No "XP", no "Sign in".
- Every number shown on the page is computed from the registry (`labStats`), never typed as a literal in JSX.
- Tailwind v4 only generates classes it sees as literal strings: animation delays are inline `style={{ animationDelay }}`, never built class names.
- Orange **text** uses `text-brand-strong`; orange fills, bars, dots, caret and glows use `brand`. `text-faint` is only for line numbers, separators and decoration.
- `HomePage.tsx` and `HeroDemo.tsx` must never import `QueryEditor`, `monacoSetup`, `useLabEngine`, `CheckBanner` or `Markdown`.
- Content files under `content/` are not touched.
- Verification commands: `npm run typecheck`, `npm test` (or `npx vitest run <file>`), `npm run e2e` (or `npx playwright test -g "<name>"`). The Playwright config starts its own dev server on port 5199.

## Review Focus

1. **Content fails to load** (`getLab('sql')` is undefined): the page must still render with only coming-soon cards, no stats, no CTA banner, and no thrown error. Pinned in Task 6 (`HomePage.test.tsx`, "renders without the SQL lab").
2. **A lab goes live later** (e.g. `content/postgres/` is added with title "PostgreSQL Lab"): it must vanish from the coming-soon list in navbar, grid and footer at once. Pinned in Task 1 (`registry.test.ts`, "upcomingLabs drops names that are live").
3. **Demo rows drift** from `shop.sql`: the hero must never show a false result. Pinned in Task 4 (`scripts/homeDemo.test.ts`).
4. **Narrow screens**: the overhanging "Correct!" pill and the hero glow must not cause sideways scrolling or get clipped at 375px. Pinned in Task 7 (e2e "never scrolls sideways").
5. **Existing lab e2e tests** start at `/` and would land on the home page. Pinned in Task 7 (`openFirstLesson` moves to `/sql`; the full suite is run).

import type { Lab } from '@codeadda/core';
import type { UpcomingLab } from '../content/registry';
import { flatItems, itemPath } from '../lab/navigation';
import type { IconName } from './icons';

// Pure data and helpers for the home page. No React and no registry import, so node tests can load it.

export interface LabStats {
  chapters: number;
  lessons: number;
  problems: number;
  /** Lessons that ship a "Watch it happen" step script. */
  animated: number;
  total: number;
  firstLesson?: string;
  firstProblem?: string;
}

export function labStats(lab: Lab): LabStats {
  const lessons = flatItems(lab, 'lessons');
  const problems = flatItems(lab, 'problems');
  return {
    chapters: lab.lessons.length,
    lessons: lessons.length,
    problems: problems.length,
    animated: lessons.filter((i) => i.steps).length,
    total: lessons.length + problems.length,
    firstLesson: lessons[0] ? itemPath(lab.id, 'lessons', lessons[0].id) : undefined,
    firstProblem: problems[0] ? itemPath(lab.id, 'problems', problems[0].id) : undefined,
  };
}

export type Tone = 'comment' | 'keyword' | 'function' | 'number' | 'plain';
export type Token = [Tone, string];

export interface HeroDemo {
  file: string;
  crumb: string;
  lines: Token[][];
  columns: readonly [string, string];
  rows: readonly (readonly [string, number])[];
}

/**
 * The hero's example. The rows are the real answer on content/sql/datasets/shop.sql
 * (India ×3, USA ×3, Japan ×2, every other country ×1); scripts/homeDemo.test.ts re-runs it on PGlite.
 */
export const HERO_DEMO: HeroDemo = {
  file: 'shoppers.sql',
  crumb: 'SQL Lab · Grouping Data',
  lines: [
    [['comment', '-- Countries with 2+ shoppers']],
    [['keyword', 'SELECT'], ['plain', ' country, '], ['function', 'COUNT'], ['plain', '(*) '], ['keyword', 'AS'], ['plain', ' shoppers']],
    [['keyword', 'FROM'], ['plain', ' users']],
    [['keyword', 'GROUP BY'], ['plain', ' country']],
    [['keyword', 'HAVING'], ['plain', ' '], ['function', 'COUNT'], ['plain', '(*) > '], ['number', '1']],
    [['keyword', 'ORDER BY'], ['plain', ' shoppers '], ['keyword', 'DESC'], ['plain', ', country;']],
  ],
  columns: ['country', 'shoppers'],
  rows: [['India', 3], ['USA', 3], ['Japan', 2]],
};

export function demoSql(demo: HeroDemo): string {
  return demo.lines.map((line) => line.map(([, text]) => text).join('')).join('\n');
}

export interface UpcomingCopy {
  tagline: string;
  description: string;
  icon: IconName;
}

/** Card copy for labs that are announced but not built. Adding a name to UPCOMING_LABS without copy here fails typecheck. */
export const UPCOMING_COPY: Record<UpcomingLab, UpcomingCopy> = {
  PostgreSQL: { tagline: 'The Postgres extras', description: 'Planned: JSONB, arrays, indexes and reading a query plan.', icon: 'layers' },
  MongoDB: { tagline: 'Think in documents', description: 'Planned: filter, shape and aggregate JSON-style documents instead of rows.', icon: 'braces' },
  Redis: { tagline: 'Data at memory speed', description: 'Planned: keys, lists, sets and hashes, the pieces behind caches and leaderboards.', icon: 'bolt' },
};

export interface Step {
  title: string;
  body: string;
}

export const STEPS: Step[] = [
  { title: 'Pick a lesson', body: 'Each lesson explains one idea in a few short paragraphs, then hands you a task that puts it to work.' },
  { title: 'Run your query', body: 'Write SQL in the editor and press Run. A Postgres database living in your browser returns real rows.' },
  { title: 'Get a verdict', body: 'CodeAdda compares your result with the expected one and, when they differ, shows you exactly which rows.' },
];

export interface Feature {
  icon: IconName;
  title: string;
  body: (stats?: LabStats) => string;
}

export const FEATURES: Feature[] = [
  { icon: 'chip', title: 'No server, no setup', body: () => 'Postgres runs inside the page itself. No install, no account, and your queries never leave your machine.' },
  { icon: 'check-circle', title: 'Graded on results', body: () => 'Your rows are compared with the expected rows, not the text you typed, so any correct query passes.' },
  { icon: 'eye', title: 'Watch it happen', body: (s) => `${s ? s.animated : 'Lessons'}${s ? ' lessons' : ''} animate what a clause does, step by step, before you try it yourself.` },
  { icon: 'bookmark', title: 'Your place, saved', body: () => 'Progress and drafts stay in this browser, so you can close the tab and pick up later.' },
