Tables usually need an id that numbers itself. PostgreSQL has two ways to do that.

The older one is `serial`:

```sql
CREATE TABLE tags (
  id serial PRIMARY KEY,
  label text
);
```

`id serial` is shorthand for an integer column with `DEFAULT nextval(...)` from a separate sequence; anyone can insert their own id, which later collides with the sequence.

`GENERATED ALWAYS AS IDENTITY` is the SQL-standard form: an INSERT that supplies an id is rejected unless it says `OVERRIDING SYSTEM VALUE`; `GENERATED BY DEFAULT` allows it.

```sql
CREATE TABLE audit_logs (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  action text NOT NULL
);
```

## Context

`information_schema.columns` tells you whether a column is an identity column, and which kind:

```sql
CREATE TABLE stickers (id integer GENERATED BY DEFAULT AS IDENTITY, label text);
SELECT column_name, is_identity, identity_generation
FROM information_schema.columns
WHERE table_name = 'stickers';
```

## Task

Create a table named `coupons` with two columns:
- `id`: an `integer` primary key that PostgreSQL always generates itself, and that rejects ids supplied by an `INSERT`
- `code`: `text`

## Hint

- You want the SQL-standard identity syntax, not `serial`.
- Of the two identity variants, pick the one that refuses manual ids.

## Solution

```sql
CREATE TABLE coupons (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  code text
);
```
